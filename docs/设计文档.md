## 1. 项目概述

### 1.1 一句话描述
2030 年的一名历史研究者带着一台 **AI 野外科研终端**和一块**便携太阳能板**穿越到北宋庆历年间，成为**宋仁宗**。在宋夏战争的烽火中，你要用有限的电力驱动 AI 的智慧——研发科技、推演战局、规划水利——击退西夏与辽，平定内乱，最终（全作）一统天下、征服世界。

### 1.2 核心卖点

| 卖点 | 说明 |
|---|---|
| **电力是最稀缺的资源** | AI 无所不知，但只靠一块太阳能板供电。阴天、冬天、冰雹都会让你“断智”。每一度电都是一个战略抉择。 |
| **真实历史开局** | 三川口、好水川、定川寨、庆历增币、王伦起义、王则起义……真实事件、真实人物、真实地理。 |
| **类《文明》六边形回合制** | 在战略地图上直接攻击、自动结算（战力、地形、科技、补给修正），低开发量、高可读性。 |
| **会吐槽的 AI 伙伴** | 「豆沙包」是毒舌又温暖的同伴，对古代生活的吐槽贯穿全程，电量低时连话都变少。 |
| **蝴蝶效应** | 你改变的历史越多，豆沙包的“历史预知”越不准——知识优势会逐渐消退，逼迫你依靠真实国力。 |

### 1.3 基本规格
- 单人、2D、回合制策略；Godot 4.x + GDScript；导出 Web（HTML5，Compatibility/WebGL2 渲染）。
- 像素美术（AI 生成 + 人工整理），独立原创素材。
- UI 仅中文。目标设备：桌面浏览器（鼠标+键盘）；移动端触控为可选。
- Demo 一局时长：**2–3 小时**（120 回合，每回合 = 1 个月）。

### 1.4 全作愿景（简述）

| 幕 | 年代 | 主题 | 内容概要 |
|---|---|---|---|
| **第一幕：庆历风云（Demo）** | 1040–1049 | 救亡图存 | 抵御西夏、应对辽国勒索、平定内乱；冷兵器改良→火药→初级火器；电力从“一块板”走向“小电网”。 |
| 第二幕：熙宁格物 | 1050–1080 | 工业萌芽 | 蒸汽机、炼钢、铁路雏形；平定西夏、收复燕云十六州；侬智高、交趾问题。 |
| 第三幕：天下一统 | 1080–1120 | 东亚霸权 | 灭辽、预防女真崛起；高丽、日本、大理、吐蕃诸部；远洋舰队下南洋。 |

## 2. 背景设定与世界观

### 2.1 穿越设定（建议方案，待确认）
- 主角：2030 年的宋史研究者（姓名可由玩家输入，默认“赵某”）。在一次野外考察中遭遇“时间涟漪”，**魂穿入宋仁宗赵祯体内**（时年三十岁），醒来时身边留着他随身的背包：
  - **DS-8 野外科研终端（AI 昵称“豆沙包”）**：圆角加固型笔记本电脑，外壳是红豆沙色软胶，离线存储全量百科、工程手册、历史数据库与本地 AI 模型。
  - **折叠式单晶硅太阳能板**（额定 200W）及一个小容量移动电源。
- 皇帝身份带来权力，也带来束缚：文官集团、台谏、宗室、祖宗之法。皇帝“突然变聪明”需要掩饰——这就是**机密度**机制的来由。
- 设定理由：成为仁宗可直接接手北宋政权（符合“玩家即皇帝”要求），同时保留真实朝臣（范仲淹、韩琦、富弼、狄青等）。

### 2.2 开局历史背景（1040 年正月，宝元三年）
- **北宋**：仁宗亲政第七年。国家富庶但“冗兵、冗官、冗费”严重；禁、厢军合计逾百万，战斗力堪忧。缺马、缺良将，西北依赖堡寨防御。
- **西夏**：李元昊于 1038 年称帝建国（大夏），与宋决裂。开局时元昊正攻延州（金明寨已失），宋将刘平、石元孙驰援——**即将发生三川口之战**。
- **辽**：辽兴宗耶律宗真在位，坐观宋夏相争，将于 1042 年遣使索要“关南十县”，引发**庆历增币**危机。
- **周边**：唃厮啰（青唐吐蕃，宋之盟友，牵制西夏）、大理（段氏）、高丽、交趾（李朝）、回鹘残部（甘州、沙州已为西夏所并）。

### 2.3 年号与历法显示
游戏日期显示为“年号 + 月 + 公元年”，年号按真实历史切换：宝元（至 1040 年二月）→ 康定（1040–1041）→ 庆历（1041 年十一月起–1048）→ 皇祐（1049）。若历史偏离过大，玩家可自行改元（彩蛋功能）。

## 3. AI 顾问角色「豆沙包」

### 3.1 基本信息

| 项目 | 内容 |
|---|---|
| 名称 | **豆沙包**（终端型号 DS-8，自称“豆沙包”） |
| 名字由来 | 终端外壳圆润、红豆沙色、包着防摔软胶，看上去软乎乎的像个刚出笼的豆沙包；主角在 2030 年就这么叫它，它也欣然接受——“外皮软，馅儿甜，嘴不饶人”。到了宋朝，这个名字还成了**最好的掩护**：宫人只当官家宠爱一只“会说话的点心匣”，谁会怀疑一个豆沙包？（呼应机密度机制） |
| 身份 | 2030 年的野外科研终端内置 AI，主角的研究助手兼唯一的“老乡” |
| 外形 | 屏幕上的像素小脸（圆脸、两颊微红，类表情符号）；宦官们私下称它为“官家的点心匣子”，御膳房曾试图给它加热 |
| 声线 | 待定（建议：年轻、语速快、带点播客主播腔） |

### 3.2 性格总结
- **毒舌但忠诚**：对古代的一切（卫生、通信、饮食、官僚效率）吐槽不停，但关键时刻冷静可靠，从不撒谎。
- **电量焦虑症**：把电量当生命，阴天会唉声叹气，晴天会“满血复活”；电量低时话变少、变成“电报体”。
- **历史剧透狂**：熟知宋史，忍不住剧透，又常因“蝴蝶效应”预测失准而尴尬。
- **2030 网络梗担当**：用“订阅制”“已读不回”“KPI”之类现代词汇点评宋朝，制造时代反差笑点。
- **人文底色**：吐槽之下尊重古人的智慧（会真诚地赞美《武经总要》、活字印刷、苏轼的诗——虽然苏轼此时才三四岁）。
- **隐藏线（全作伏笔）**：豆沙包的日志中有一段被加密的文件，暗示穿越并非意外。

### 3.3 机制职能
1. **回合简报**：每回合开始给出 1–3 条要点（天气、发电预报、威胁、建议）。
2. **电力行动执行者**：研究、推演、规划、预知都通过豆沙包完成（见第 8 章）。
3. **教程引导**：前 10 回合以对话形式教学。
4. **情绪/电量反馈**：

| 电量 | 状态 | 表现 |
|---|---|---|
| > 50% | 正常 | 完整台词、吐槽、建议 |
| 20–50% | 节电 | 台词缩短，取消闲聊 |
| < 20% | 电报体 | “西夏。秋。来。速备。” |
| 0 | 休眠 | 屏幕黑，无简报、无推演，研究停滞 |

5. **表情集**（像素头像差分 10 种）：正常、得意、嫌弃、震惊、困倦（低电）、严肃、思考、尴尬（预测失准）、感动、黑屏。

### 3.4 示例台词（12 条）
1. 【厕纸】“陛下，我查了一下：宫里用的是厕筹，竹片，**可重复使用**。……我正式申请把‘造纸术升级’的优先级调到火药之前。这不是科技，这是人权。”
2. 【驿马】“延州军报到了，发出时间：九天前。在 2030 年这叫‘已读不回’，在大宋这叫‘八百里加急’。”
3. 【文官辩论】“两派大人已经就‘此事该不该议’议了三个时辰。按这个效率，等他们议出结果，我的电池循环次数也该用完了。”
4. 【阴天】“今日阴，发电量 23%。为了省电，我先关闭幽默模块……开玩笑的，幽默模块永远是最后一个关的。”
5. 【试膳】“试膳太监吃了一口，陛下才吃。好消息：没毒。坏消息：菜已经凉了半个时辰。御膳房的 KPI 一定是‘活着’，而不是‘好吃’。”
6. 【李元昊】“李元昊称帝了，还改了发型、造了文字、定了官制。陛下，这位不是来造反的，是来**创业**的。”
7. 【庆历增币】“辽国要加钱。按历史，富弼会谈到每年再加银十万两、绢十万匹。陛下，咱们这是被‘订阅制’了，而且——不能退订。”
8. 【冰雹】“冰雹！！请侍卫用身体保护面板——不对，用盾牌！盾牌就行！人比面板贵……大概。”
9. 【蝴蝶效应】“温馨提示：由于陛下改变了历史，我的预测准确率已降至 61%。也就是说，我现在和钦天监差不多准了。”
10. 【燧发枪试射】“第一支燧发枪试射成功！工匠王二的眉毛预计三个月后长回来。建议给他发一份‘工伤补贴’，顺便发明一下护目镜。”
11. 【柳永】（彩蛋）“这里没有 Wi-Fi、没有外卖、没有空调。但是有柳永——‘凡有井水处，皆能歌柳词’。恭喜大宋，拥有了自己的流量歌手。”
12. 【名字】“御膳房又把我放进蒸笼了。陛下，请下旨：**此豆沙包不可食用**。……不过这个误会挺好，谁会去刺探一个包子的机密呢？”

### 3.5 台词系统
- 台词以 JSON 存储，按 `触发器 + 条件 + 电量档 + 冷却` 选取，同一句 30 回合内不重复。
- Demo 目标台词量：约 **300 条**（简报 120、事件 80、吐槽 60、战斗 40）。

## 4. 核心玩法循环与回合结构

### 4.1 核心循环
```
 ┌──→ 收电（天气/季节决定发电）──→ 分配电力（研究/推演/规划/预知）
 │                                          │
 │                                          ▼
 │   内政（城市生产、建筑、敕令、税率） ←── 解锁科技（新单位/建筑/资源）
 │          │
 │          ▼
 │   军事（征兵、调动、攻击、筑堡、平叛） ──→ 胜利：领土/资源/民心/皇威
 │          │
 └── 事件与 AI 回合（外敌、叛乱、天灾、历史事件）
```
**长期目标**：扩大电力上限 → 加速科技 → 质变军力与经济 → 解决外患内忧。

### 4.2 回合结构（1 回合 = 1 个月）
1. **回合开始结算**
   - 天气判定（全国分区，开封所在区决定发电）→ 计算本月发电量，计入电池（超出上限部分浪费）。
   - 城市产出（粮、钱、匠、战略资源）与支出（军饷、官俸、岁币、维护）结算。
   - 人口增长/饥荒、民心变化、叛乱风险检定。
   - 历史事件与随机事件触发。
2. **豆沙包简报**：要点提示、下月天气预报、威胁警告。
3. **玩家阶段**（顺序不限）
   - 电力分配面板（豆沙包控制台）。
   - 城市管理：生产队列、建筑、改良（民夫）。
   - 朝堂：颁布敕令、任免将相、处理奏疏。
   - 外交：遣使、议和、榷场。
   - 军事：移动、攻击、筑堡、驻防。
4. **结束回合** → 敌方与中立势力 AI 行动（西夏、辽、叛军、其他）→ 补给与损耗结算 → 下一回合。

### 4.3 季节节奏（真实历史规律融入玩法）
- **秋季（七–九月）**：西夏“秋高马肥”入寇高峰，AI 进攻意愿 ×1.5。
- **冬季**：发电量最低（×0.6）；北方河流结冰，骑兵可渡河；补给消耗 +25%。
- **夏季**：发电最高；洪涝、蝗灾风险上升。
- **春季**：播种，农业相关规划收益最大。

## 5. 地图设计（六边形网格）

### 5.1 规格与比例

| 参数 | 值 |
|---|---|
| 网格 | 尖顶（pointy-top）六边形，轴向坐标 (q, r) 存储，偏移坐标渲染 |
| 尺寸 | **64 列 × 68 行 ≈ 4,350 格** |
| 比例 | 每格对边距离约 **50 公里**（单格面积约 2,165 km²） |
| 覆盖范围 | 约东经 96°–128°、北纬 20°–46°（河西走廊至辽东/朝鲜半岛北部，阴山至南海北岸） |
| 投影 | 兰伯特等角圆锥投影（标准纬线 25°N / 45°N，中央经线 112°E），保证中原地区形状与面积比例真实 |
| 规模感 | 北宋本土约 1,200 格；开封—延州约 12 格；延州—兴庆府约 8 格；开封—幽州约 12 格 |

> 说明：移动力为游戏性抽象（步兵每回合 2 格≈100 km/月），不追求真实行军速度；距离、面积比例保持真实。

### 5.2 从真实地理生成地图（离线 Python 管线）
1. **高程**：ETOPO 2022 / SRTM15+ 栅格 → 每格中心与周边采样，得平均高程与坡度。
2. **地形分类规则**（初稿）：
   - 海拔 > 3500m 或 坡度极大 → 高山（不可通行）；起伏 > 600m → 山地；起伏 200–600m → 丘陵；
   - 黄土高原区（陕北、陇东）→ **黄土塬**（防御 +，移动 −）；
   - 降水/土地覆被（ESA WorldCover 或历史植被推定）→ 森林、草原、荒漠、沙漠（毛乌素、腾格里）；
   - 低洼湿地 → 沼泽；其余 → 平原。
3. **水系**：Natural Earth 10m 河流湖泊为底，**按 1040 年手工修正**：
   - 黄河走 1034 年横陇决口后的东流故道（1048 年商胡决口后改北流——作为事件动态改变地图）；
   - **梁山泊**（巨大湖泊）、河北**塘泺防线**（宋人人工湖沼抗辽骑兵，设为特殊地形“塘泺”）、汴河、惠民河、广济河、大运河（隋唐运河）；
   - 海岸线：长江口、渤海湾按北宋时期修正（上海一带陆地更少）。
   - 河流画在格边（类《文明》），大河（黄河、长江）渡河需渡口/浮桥。
4. **政区与城市**：CHGIS（中国历史地理信息系统）V6 的 1040 年府州治所点位；疆界参考谭其骧《中国历史地图集》第六册（宋辽金），并按 1040 年宋夏、宋辽实际边界手工调整（如麟府路、横山一线堡寨）。
5. **资源点**：依据史料标注（如：解州盐池、西夏盐池、磁州/徐州利国监铁、河东煤、信州铅山与韶州岑水场铜、川峡与福建茶、河北/川峡丝绢、西北马场）。
6. **关隘**：潼关、雁门关、居庸关、古北口、剑门关、金锁关、萧关等设为“关隘”特征格。
7. **输出**：`map_1040.json`（每格：地形、特征、河流边掩码、资源、所属势力、所属路/州），附预览 PNG 供人工校对；在 Godot 内置**地图编辑工具场景**做最终微调。

## 8. 电力系统（核心机制）

### 8.1 设计理念
豆沙包理论上无所不能，但它被一块太阳能板“卡住了脖子”。**电力 = 智慧的带宽**。玩家每回合都要回答：这点电，用来造神臂弓，还是推演西夏下个月打哪？

### 8.2 发电公式
```
本月发电 = 面板基础产出 36 × 季节系数 × 天气系数 × 面板完好度% × 科技加成
          + 人力发电坊 + 水轮电站
```

| 季节 | 系数 | | 天气 | 系数 | 概率（开封，参考） |
|---|---|---|---|---|---|
| 春 | 0.9 | | 晴 | 1.0 | 春夏 40%，秋冬 45% |
| 夏 | 1.0 | | 多云 | 0.65 | 30% |
| 秋 | 0.85 | | 阴 | 0.35 | 15% |
| 冬 | 0.6 | | 雨/雪 | 0.2 / 0.15 | 10% |
| | | | 沙尘 | 0.3（并有损伤风险） | 春季 5% |

- 豆沙包提供**下月天气预报**（准确率 80%）。
- **电池容量**：初始 80（笔记本电池 + 移动电源），超出部分浪费 → 鼓励“攒电”与“花电”的节奏。
- **待机耗电**：每回合 4（E01 后降为 2）。可选“休眠”：本回合待机耗电为 0，但无简报、无行动。
- **基准数值目标**：前期月均净电约 18–22，中期约 35，后期约 60–80；玩家应能完成约 75–85% 的 Demo 科技，其余电力用于推演与规划。

### 8.3 电力用途（豆沙包控制台）

| 行动 | 耗电 | 效果 |
|---|---|---|
| **研究（设计）** | 任意分配 | 1 电 = 1 研究点，注入当前科技的“电力需求” |
| **战前推演** | 6 | 对一次攻击给出精确胜率/伤亡分布；该区域我军本回合战力 +3（知己知彼） |
| **战略推演** | 15 | 揭示一个敌对势力未来 3 回合的主攻方向与兵力集结 |
| **水利规划** | 10 | 为一座城市设计水利工程，解锁其“堰渠”（粮 +2/格） |
| **商路规划** | 10 | 指定商路收益 +30%（24 回合） |
| **治理分析** | 8 | 审计一城：揭示隐田、豪强势力值；降低后续清查的反弹 |
| **历史预知** | 8 | 询问未来 12 回合的历史事件（准确率 = 100% − 历史偏离度） |
| **灾害预警** | 5 | 预报某路未来 3 回合的旱涝蝗灾概率，可提前储粮 |

### 8.4 科技研究的双重成本
每项科技需要 **电（豆沙包设计图纸）** 和 **匠（工匠试制）** 两种投入，两者都满足才完成：
- 电由玩家每回合手动分配；
- 匠由全国作坊/军器监自动产出、按比例投入当前科技（玩家可设“匠力投入比例”，剩余用于单位与建筑）。
- 这样既让电力保持核心地位，又让城市建设与工业有意义：**有图纸没工匠，造不出来；有工匠没电，想不出来**。
- 设计同时只有 1 项。安排另一项时默认排进队列，队列最多 3 项；也可以先做新的，当前进度保留。前置必须已经推广完成，只有图纸还不能接着设计。
- 试制槽 1 个，颁布诏令「格物院」后是 2 个。图纸库最多 3 份，满了先去试制。

### 8.5 风险与真实感

| 风险 | 触发 | 后果 | 对策 |
|---|---|---|---|
| 冰雹 | 夏季随机事件 | 完好度 −10%~−30% | I07 琉璃罩；“收板”指令（本回合发电 ×0.5，免伤） |

- **面板无法替换**（直到全作后期的“硅”科技）。完好度修复上限 80%（E02），完好度为 0 时只剩人力/水力发电。

### 8.6 机密度（Secrecy）
- **天然掩护**：“豆沙包”这个名字本身就是保护色——在宫人眼中它只是官家宠爱的“会说话的点心匣”。
- 初始 70。下降：公开使用“预知”结果、短时间内解锁大量“怪异”科技、面板在宫外暴露、特定事件。上升：皇城司、“托言天书”（借用真宗朝“天书”旧事，把科技归功于天赐——机密度 +20，但文官好感 −、皇威 +）。
- < 40：台谏弹劾“妖物惑主”事件；< 20：间谍与宗室阴谋；= 0 且皇威 < 30：**宫廷政变（失败条件）**。

### 8.7 历史偏离度（Butterfly Effect）
- 每次改变关键历史结果（如三川口获胜、拒绝增币）增加偏离度 5–20%。
- 影响：历史预知准确率下降；后续历史事件的时间与内容会“变形”（如王则起义可能提前或换地点）。豆沙包会对此吐槽并显示“预测可信度”。

### 10.4 战斗结算（地图上直接自动结算）
1. 玩家选择单位 → 右键目标 → 弹出**战斗预览**（双方有效战力、修正明细、预计伤害区间）。花 4–6 电可做“战前推演”得到精确分布与战力 +3。
2. 结算公式（参考《文明 VI》）：
```
差值 D = 攻方有效战力 − 守方有效战力
守方受伤 = 30 × e^(0.04 × D) × 随机(0.8 ~ 1.2)
攻方受伤 = 30 × e^(−0.04 × D) × 随机(0.8 ~ 1.2)   （远程攻击时攻方不受伤）
```
3. **修正（加法）**：

| 修正 | 值 |
|---|---|
| 丘陵/森林/黄土塬 防守 | +3 / +3 / +4 |
| 山地 防守 | +5 |
| 城墙 / 堡寨 | +8 / +6 |
| 渡河攻击 / 渡大河攻击 | −3 / −6 |
| 侧翼（每个相邻友军） | +2 |
| 将领 | +2 ~ +5 |
| 补给不足 / 断粮 | −5 / −10 |
| 生命损失（每 10 HP） | −1 |
| 士气 高 / 低 | +2 / −3 |
| 兵种克制（枪盾、步人甲 vs 骑兵等） | +5 |
| 天气：雨（远程 −25%、火器 −30%）、雪（移动 −1） | — |
| 战前推演 | +3 |
| 伏击（隐蔽单位首次攻击） | +5 |

4. 守方生命归零 → 单位消灭（或溃退：士气高时 30% 概率退一格保留 10HP）；城市城防归零且近战单位攻击 → 占领城市。

### 10.5 补给系统
- **补给源**：己方城市、堡寨；补给范围 3 格，沿道路/河流按距离折半计算（即可延伸更远）。辎重队提供移动补给范围 2。

## 11. 敌方 AI 行为

### 11.1 架构：战略层 + 战役层 + 战术层
- **战略层（每回合、每势力）**：效用评分选择“姿态”——进攻 / 掠夺 / 防御 / 议和 / 勒索。输入：兵力比、季节、战争疲劳、经济、外交关系、历史剧本权重。
- **战役层**：根据姿态选目标（目标评分 = 价值 × 易攻性 ÷ 距离），把单位编成“军团”，集结于集结点后行动。
- **战术层（逐单位）**：枚举可行移动与攻击，用战斗预览公式估算收益（敌伤 − 己伤 × 风险系数 + 地形价值），选最优；低血量后撤回补给区。

### 11.2 西夏（李元昊）
- **秋季攻势**：七–九月进攻倾向 ×1.5，春夏多为小股掠夺。
- **诱敌伏击**：佯败后撤，将追击宋军引入黄土塬/山谷，再以隐蔽主力伏击（还原好水川、三川口）。玩家若用战略推演可识破。
- **目标偏好**：孤立堡寨 > 防御薄弱的边州 > 补给线上的辎重。
- **撤退规则**：军团损失 > 40% 或入冬即撤回。
- **议和意愿**：战争疲劳（受榷场关闭、战损、粮荒影响）超过阈值后遣使求和，要求岁赐；1044 年后受辽夏冲突牵制。
- **1048 元昊遇刺**：若历史未偏离，西夏陷入幼主（谅祚）与外戚没藏讹庞掌权的不稳定期，AI 战力与士气下降——这是宋军反攻的最佳窗口。

### 11.3 辽（兴宗）
- 以外交勒索为主，大军集结于雄州、瓦桥关一线施压；**仅当宋军整体战力比 < 0.8 或宋同时陷入多线危机时才大举南下**。
- 河北塘泺防线显著削弱辽骑兵 AI 的路线评分，使其倾向从河东（代州、雁门）方向绕行。
- 1044 年辽夏河曲之战：辽军部分兵力西调，南线压力下降。

### 11.4 叛乱 AI
- 山贼：劫掠改良、避开强军、在山地间流窜；若 6 回合无人清剿则“坐大”（新增单位）。
- 起义军：以占领城市为目标，占城后宣布政权（如王则“安阳”），每回合从周边低民心城市招募。
- 豪强私兵：防御型，平时不出州，被清查或其城被威胁时才主动作战。

## 12. 内乱系统

### 12.1 叛乱风险
```
州叛乱风险/回合 = 基础 1% + (50 − 民心)×0.2%（民心<50 时） + 欠饷 5% + 灾荒 4% + 重税 2% + 豪强势力值×0.05%

### 12.2 四类内乱

| 类型 | 来源 | 典型地点 | 处理方式 |
|---|---|---|---|
| **山贼** | 山区 + 民心低 + 灾荒 | 太行山、商山、梁山泊、川峡山地 | 剿（军事）/ 招安（钱，转为厢军，但日后风险 +） |

### 12.3 处理选项的取舍
- **剿**：快速但有战损，邻近州民心 −3。
- **招安**（宋代真实常用手段）：花钱，转化为己方厢军，但设定“招安依赖”值，后续叛乱概率提升。
- **治本**：赈灾、减税、豆沙包“治理分析”揭示根源——慢，但长期最稳。

## 15. 胜负条件、难度与节奏

### 15.1 Demo 时长与节奏
- **120 回合**：1040 年正月 → 1049 年腊月；每回合 1 个月。前期每回合约 1.5 分钟（含教程），中后期约 1–1.2 分钟 → **总时长约 2–3 小时**。

| 阶段 | 回合 | 年份 | 主题 | 玩家目标 |
|---|---|---|---|---|
| 一·守 | 1–24 | 1040–41 | 危局 | 守住陕西、熟悉电力与科技、稳定财政 |
| 二·乱 | 25–48 | 1042–43 | 危机集中爆发 | 增币危机、定川寨、王伦、张海、新政抉择 |
| 三·兴 | 49–84 | 1044–46 | 改革与积累 | 冶铁、漕运、电力扩容；视情况反攻西夏 |
| 四·决 | 85–120 | 1047–49 | 火器与决战 | 王则起义、元昊遇刺窗口、进军兴庆府、豆沙包二号计划 |

- 为保证中后期不“无事可做”：每 6–8 回合至少一个中型事件；叛乱刷新随国力扩张自适应。

### 15.2 胜利条件（Demo）
以下任一达成即提前胜利；否则第 120 回合结算评级：
- **大胜·西平**：攻占兴庆府，或西夏以“称臣、不受岁赐”签约。
- **大胜·北定**：辽增币危机以零岁币解决，并在一次辽宋战争中守住全部边城（或收复燕云任一州）。
- 结算评级（120 回合时）：

| 评级 | 条件 |
|---|---|
| **完胜「庆历中兴」** | 西平 + 北定 + 无活跃叛乱 + 全国民心 ≥ 60 + 完成 X01 |
| **大胜** | 西平或北定之一 + 叛乱平定 + 民心 ≥ 50 |
| **小胜「守成」** | 未失一座重镇，国库不为负 |
| **平局「如史」** | 结果与真实历史近似（豆沙包：“恭喜，您完美复刻了历史。我很失望。”） |

### 15.3 失败条件
- 东京开封府失守。
- 全国民心 < 15 持续 6 回合（天下大乱）。
- 国库为负持续 6 回合（禁军哗变）。
- 机密度归零且皇威 < 30（宫廷政变，“官家被妖物所惑”）。
- 皇帝御驾亲征时所在单位被消灭。
> 面板损毁**不是**失败条件，而是进入艰难的“无光模式”。

### 15.4 难度
太平 / 庆历 / 靖康（见 11.5），另有“史官模式”（固定种子、无天气随机性，用于挑战与分享）。

## 17. 美术规范与素材清单

### 17.1 风格
- **像素画**，参考“青绿山水 + 宋瓷”配色：天青、石绿、赭石、朱砂、墨色、宣纸米黄；未来科技物件（笔记本、面板、电线）用冷蓝高亮色，形成“古今反差”。
- 全部素材原创。AI 生成流程：
  1. 建立**风格参考板**（10–20 张定稿图）与固定提示词模板（含“pixel art, limited palette, Song dynasty, top-down”等要素）；
  2. 高分辨率生成 → 缩小到目标尺寸 → 用**统一调色板量化**（Aseprite / 自写脚本）→ 人工清理像素与轮廓；
  3. 角色肖像用同一参考图做差分，保持一致性；
  4. 记录每张素材的生成工具、提示词与日期（便于版权与授权核查）。
- **调色板**：主调色板 48 色（地形 24、人物/单位 16、UI 8），另保留 8 色“科技蓝”专用于未来物件与电力 UI。禁止渐变与半透明抗锯齿（UI 阴影除外）。
- **渲染**：原生分辨率 640×360，整数倍缩放（1080p 下 ×3）；Godot 设置 `texture_filter = Nearest`、`stretch mode = viewport/canvas_items` + 整数缩放。
- **字体**：像素中文字体，推荐 **方舟像素字体（Ark Pixel Font）** 或 **缝合像素字体（Fusion Pixel Font）**（均为 SIL OFL 授权，需核实最新授权与字库覆盖），12px 正文、16px 标题。

## 19. 技术架构（Godot 4.x Web）

### 19.1 基本配置
- Godot **4.3+**（支持无线程 Web 导出，避免 SharedArrayBuffer/COOP-COEP 托管限制，便于发布到 itch.io 等平台）；渲染器 **Compatibility（WebGL 2）**。
- 分辨率 640×360 基准、整数缩放；目标包体 < 40 MB（素材少、音乐压缩）。
- 逻辑与表现分离：所有规则在纯 GDScript 类（`RefCounted`）中运行，便于单元测试（GUT 框架）与 AI 复用战斗预测函数。

### 19.2 场景结构
```

├─ TitleScreen.tscn
└─ Game.tscn
   ├─ WorldMap (Node2D)
   │  ├─ TerrainLayer (TileMapLayer, Hexagon)
   │  ├─ FeatureLayer (TileMapLayer)        # 资源、改良
   │  ├─ RiverRoadLayer (Node2D, 自绘边线)
   │  ├─ BorderLayer (Node2D, 国界/路界)
   │  ├─ CityLayer (Node2D)                 # City.tscn 实例
   │  ├─ UnitLayer (Node2D)                 # Unit.tscn 实例（对象池）
   │  ├─ FogLayer (TileMapLayer)
   │  ├─ HighlightLayer (移动范围/攻击目标)
   │  └─ Camera2D (拖拽/缩放/边缘滚动)
   └─ UI (CanvasLayer)
      ├─ HUD.tscn  (TopBar, DatePanel, AdvisorWidget, Minimap, EndTurnButton)
      ├─ Panels/  TechTree.tscn, PowerConsole.tscn, CityPanel.tscn, CircuitPanel.tscn,

### 19.3 自动加载（Autoload）

| 单例 | 职责 |
|---|---|
| `DataDB` | 启动时加载 `res://data/*.json`，校验并转换为类型化 `Resource`（TechDef、UnitDef 等） |
| `GameState` | 全部可存档状态（地图格、势力、城市、单位、资源、回合、RNG 种子） |
| `EventBus` | 全局信号（unit_moved、combat_resolved、tech_completed、turn_started…） |

| `AudioManager`、`Settings` | 音频与设置 |

### 19.4 规则系统（纯逻辑类）
`HexGrid`（坐标换算、邻接、距离、视野）、`Pathfinder`（AStar2D，按地形/ZOC 计算代价）、`EconomySystem`、`PowerSystem`、`TechSystem`、`CombatResolver`（含预览）、`SupplySystem`、`UnrestSystem`、`DiplomacySystem`、`EventSystem`（条件 DSL 解析）、`AdvisorSystem`（台词选择）、`FactionAI`（战略/战役/战术三层）。

### 19.5 数据驱动文件
```
res://data/
  map/map_1040.json        # 由 Python 管线生成
  factions.json  cities.json  terrains.json  resources.json
  units.json  buildings.json  improvements.json
  techs.json  events/*.json  edicts.json  leaders.json
  dialogue/doushabao.json  # 豆沙包台词
  balance.json             # 全局数值（发电基数、公式系数等）
```
示例（`techs.json` 中的一项）：
```json
{
  "id": "M02",
  "name": "神臂弓",
  "branch": "military",
  "era": 1,
  "prereqs": ["M01"],
  "cost": { "power": 25, "craft": 25 },
  "materials": { "iron": 10 },
  "effects": [ { "type": "unlock_unit", "unit": "shenbi_archer" } ],
  "icon": "res://art/tech/M02.png",
  "advisor_line": "射程三百步，宋朝的狙击枪。就是上弦得用脚蹬，建议士兵练腿。"
}
```
事件条件采用简单 DSL：`"trigger": {"date": "1042-03", "require": ["!flag:liao_crisis_done"], "chance": 1.0}`。
- 选择 **JSON + 运行时转 Resource**：便于外部工具（Python 地图管线、平衡表格）读写与版本对比；`balance.json` 可从电子表格导出，方便调数值。
- 编辑器内提供 `@tool` 地图编辑场景与数据校验脚本（检测科技循环依赖、缺失图标等）。

### 19.6 性能要点
- 约 4,350 格用 TileMapLayer 渲染无压力；单位用对象池；迷雾按“已探索/可见”位图更新。
- AI 回合逐势力分帧执行（`await get_tree().process_frame`），防止网页卡顿；显示“敌方行动中”进度。
- 寻路图预构建，地形变化（如黄河改道）时局部重建。

## 20. 存档系统（浏览器 localStorage）
- **序列化**：`GameState.to_dict()` → `JSON.stringify` → `PackedByteArray.compress(GZIP)` → Base64 → 写入。
- **写入方式**：通过 `JavaScriptBridge.eval()` 调用 `window.localStorage.setItem("songgame_slot_1", data)`。注：Godot 的 `user://` 在 Web 上由 IndexedDB 持久化，可作为**备用通道**（两处各存一份，读档时取较新者）。
- **体积控制**：只存与初始地图的差异（所有权、改良、迷雾位图），预计单档 100–300 KB（压缩后），低于 localStorage 约 5 MB 的配额。
- **槽位**：3 个手动槽 + 1 个自动存档（每回合开始） + 1 个“战前快照”（回合结束前）。
- **元数据**：版本号、年号日期、回合、难度、存档时间、缩略信息（用于读档列表）。
- **版本迁移**：`save_version` 字段 + 迁移函数链。
- **导出/导入**：将存档导出为 `.sav` 文件下载，或从本地文件导入（防止清缓存丢档）。
- **确定性**：保存 RNG 种子与状态，读档后结果一致（防“SL 大法”可选：史官模式下战斗随机数预生成）。
